## Non-blocking I/O
![[Pasted image 20260520200709.png]]
是让 Gateway 不因等待外部 I/O 而阻塞主线程；等待期间可以继续调度其他事件，从而提高并发能力、响应性和资源利用率。
比如说我有一个http请求，同时又有一个调用画图工具的任务，如果http超时，我不会等着他，而是等待的时候顺便调用画图工具
## Event
![[Pasted image 20260520201539.png]]
所有进入 Gateway 队列的原始用户请求，都会被标准化成系统可以执行/调度的事件
**任何在前端或者任何地方的所有进入系统的输入，都会被抽象为event的形式**
## Single Thread Main Loop
![[Pasted image 20260520205058.png]]
Node.js 的**事件循环**主线程，反复检查有没有事件需要处理
```
while (Gateway 没有退出) {
    1. 检查事件队列里有没有事件
    2. 取出一个事件
    3. 执行这个事件对应的 handler
    4. 如果 handler 发起异步 I/O，就登记回调，然后立刻返回
    5. 继续处理下一个事件
    6. 某个 I/O 完成后，把结果重新放回事件队列
}
```
Main Loop 是一个很轻的事件处理循环，他不具体解决任务，而是把大任务派发给别的地方做。不过它会执行一些**轻量逻辑**

**登记回调**
读文件->打印->干其他事的同步写法
```
const data = readFileSync("config.json");
console.log(data);
console.log("继续处理别的事");
```
异步写法就是
```
fs.readFile("config.json", "utf8", (err, data) => {
  console.log("文件内容：", data);
});
console.log("先做别的事情");
```
Main Loop的主线程不会被阻滞，有些IO请求被交给系统处理
## Worker Thread Pool
![[Pasted image 20260521092546.png]]
承接上面的Main Loop，Pool处理的是重型任务(主循环只指挥，重活交给线程池做)
Worker Thread Pool 在其他线程里处理，处理完以后，通过 Promise callback 把结果交回 Main Loop
```
轻任务：
Main Loop 自己处理
例如：判断事件类型、路由、登记回调、更新状态

重任务：
丢给 Worker Thread Pool
例如：压缩、加密、复杂计算、同步文件操作、CPU 密集处理
```

## Limitation
### Message Queues
OpenClaw的组件之间通讯是简单的点到点
![[Pasted image 20260521152350.png]]
Message Queues可以使得组件之间的通信更加高效，同时解耦发送方和接收方。其相当于一个邮局，大家把信件给邮局，然后邮局根据给的信件的信息送信。
然而，OpenClaw并没有这样的能力
### DDS
![[Pasted image 20260521153510.png]]
DDS 是 [[未知补全#ROS(Robot Operating System)|ROS]] 这类机器人系统中常见的底层通信基础设施；OpenClaw 目前**还没有原生支持 DDS**，所以它还不能很自然地接入机器狗这类复杂机器人硬件。
