# pi-ai
![[Pasted image 20260525105526.png]]
pi-ai为不同模型服务商写适配逻辑，在这一层集中封装成统一接口
## 参数对齐
![[Pasted image 20260525105905.png]]
拿temperature举例：
对于GPT5.5和deepseek-R1，前者1.5所具有的效果和后者0.7具有的效果是相近的，pi-ai就会统一这里的度量衡
**pi-ai 用一套内部标准模型名和内部参数语义，屏蔽不同 LLM provider 的命名、字段、参数范围和采样行为差异，使上层 agent 不需要关心具体 provider**
## 划分非结构输出
![[Pasted image 20260525110316.png]]
大模型的输出有三部分：
1. 回复（自然语言）
2. tool call：用json格式，告诉agent在哪里使用什么什么工具，要执行什么，读取哪些结果
3. thinking(reasoning)：思考过程每个模型的格式不一样，这里会统一格式
## Model Handoffs
![[Pasted image 20260525111640.png]]
管理数据在一系列专用模型之间的传递与交接
每个模型的提供商有多个模型，对于一个任务用Haiku还是Opus，不仅如此，还需要处理各个模型之间的**数据交接**(Handoffs)（不过对于Haiku和Opus来说，anthropic已经处理好了内部通讯）

## Workflow
Workflow本身可能会比较简单，但是容易出现非常多的“边缘情况”，一个酒馆的Workflow可能因为顾客点了蛋糕而出现Runtime Error，我们不总是能涵盖所有Workflow，这很难，而且可能会使得Workflow变得极其繁杂——解决方法就是Pi-Runtime
## Pi-Runtime
用一个Workflow涵盖所有的Workflow
![[Pasted image 20260525164127.png]]
假设我们现在有两个用户：a和b，他们都想调用deepseek模型。a要查阅图书，b要查阅旅游攻略
1. Initialization：两个绑定
第一步：由于两个用户账号不一样，先根据user_id绑定模型
第二步：寻找之前的log——长期记忆和当前任务的对话
2. Assembly：组装生成prompt
根据两个用户不同的Query，找相关的SKILL.md（工作指南）
